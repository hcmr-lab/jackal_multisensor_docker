# Running the stack

Assumes [first-time setup](installation.md) is done.

## One-command stack (recommended)

`scripts/stack.sh` (wrapped by `make`) runs each part in its own named **tmux** session, so nothing is tied to your terminal.

| Command            | What it does                                                              |
|--------------------|---------------------------------------------------------------------------|
| `make stack`       | Kernel tuning (asks for sudo), starts container, bridge and sensors       |
| `make record`      | Starts `ros2 bag record` in `./bags`                                      |
| `make stop-record` | Stops only the recording; sensors and bridge keep running                 |
| `make stop-stack`  | Stops recorder, sensors and bridge                                        |

| Session      | Runs                                                                     | Log                       |
|--------------|--------------------------------------------------------------------------|---------------------------|
| `ms_bridge`  | `start_bridge.sh` on the host                                            | on screen                 |
| `ms_sensors` | `ros2 launch multisensor_bringup multisensor.launch.py launch_realsense:=false` in the container | `logs/sensors_<time>.log` |
| `ms_record`  | `ros2 bag record -s mcap -a -x ".*(compressed\|theora).*" --max-bag-size 2147483648 --max-cache-size 209715200` in `~/bags` | `logs/record_<time>.log` |

Typical flow after a reboot:

```bash
make stack        # sudo once, then container + bridge + sensors
make shell        # separate shell: launch rviz2 and check everything looks right
make record
make stop-record
make stop-stack
```

- `./scripts/stack.sh status` lists running sessions;
  `./scripts/stack.sh attach <bridge|sensors|record>` shows one live (detach: `Ctrl+b d`).
- Stopping sends `Ctrl+C` (SIGINT) and waits for a clean exit, so bags are closed
  properly. If the recorder or launch is still running after 20 s, SIGINT is sent
  inside the container; after 90 s it only warns and never force-kills.
- Running `make stack` / `make record` again skips sessions that already run.
- The launch and record commands come from `SENSORS_LAUNCH_CMD` and `RECORD_CMD` in `.env` (generated by `make setup`; see `.env.example`). The default launch passes `launch_realsense:=false`; remove it from `.env` to start the RealSense too.
- If the sessions don't start because of a container name conflict, see [troubleshooting.md](troubleshooting.md).

## Manual steps

```bash
./scripts/apply_on_reboot.sh   # after every reboot: kernel buffers, USB memory cap (sudo)
make bridge                    # host, keep terminal open (needs Noetic + Foxy)
make shell                     # into the container
ros2 launch multisensor_bringup multisensor.launch.py launch_realsense:=false   # drop the argument to include the RealSense
```

Record a bag from **inside the container** (custom message types):

```bash
cd ~/bags
ros2 bag record -s mcap -a -x ".*(compressed|theora).*" --max-bag-size 2147483648 --max-cache-size 209715200
```

## Everyday commands

Run `make help` for the full list.

| Task                       | Command         |
|----------------------------|-----------------|
| Start / stop container     | `make up` · `make down` |
| Open a shell               | `make shell`    |
| Rebuild the workspace      | `make rebuild`  |
| Rebuild the Docker image   | `make build`    |
| Clear build/install/log    | `make clean`    |
| Container status / logs    | `make status` · `make logs` |

Inside the container use `cb` (build all) and `cbp <pkg>` (one package); never plain `colcon build` on the host.
